# Activity: Set the Iteration Goal

**Activity ID**: 554
**Order**: 2
**Phase**: Construction
**Dependencies**: Predecessor: Activity 553 (Determine Cadence & Iteration Length)
Successor: Activity 555 (Plan the Iteration)

## Description

Set the Iteration Goal

## Guidance

## Objective

Select one outcome that can be accepted within the iteration frame and make its evidence and exclusions explicit.

## Required inputs

- Iteration Frame.
- Charter goals and gating policies.
- Ordered product/delivery backlog.
- Previous Iteration Assessment Report, open Risk/Problem tickets, and accepted/deferred IIPs when available.
- Current capacity and known dependencies.

## Procedure

1. Review gating tickets first. A `pause_new_work` concern prevents dispatch of new delivery work; a `block_release` concern must be resolved or explicitly waived by the authorized human before release.
2. Select one outcome, not a list of unrelated tasks.
3. State: beneficiary, behavior/result, quantitative or observable success measure, acceptance evidence, excluded scope, dependencies, owner, and why it fits the chosen length.
4. Link each included concern or backlog item. Do not silently absorb work discovered during assessment.
5. Update the Iteration Frame with the goal and obtain Delivery Manager/team commitment.

## Completion evidence

The frame contains one bounded goal, objective acceptance evidence, explicit exclusions, dependency owners, ticket-gate disposition, and approval. If the goal cannot fit, reduce it before invoking PIN.

## Agent

**Name**: Delivery Manager (DM)
**Description**: Single merged PM/DM role. Staffed at Kickoff. Owns the Charter, is the recipient of all Risk/Problem tickets raised by Assess the Iteration, presides over cadence meetings, and determines iteration cadence/length.
